# ADR-005: 채팅 메시지 저장 전략

- **상태**: 확정
- **일자**: 2026-02-13

---

## 맥락 (Context)

실시간 1:1 채팅 구현 시 메시지 저장 전략을 결정해야 했다. STOMP over WebSocket으로 메시지를 주고받으며, MySQL(RDS)에 영구 저장한다.

---

## 선택지 (Options)

| 선택지 | 추가 월 비용 (AWS) | 개발 공수 |
|--------|-------------------|-----------|
| 동기 DB 저장 | **$0** | 낮음 |
| Redis 버퍼 + 비동기 배치 | ~$0 | 중간 |
| Amazon MQ (RabbitMQ) | ~$95+ | 중간 |
| Amazon MSK (Kafka) | ~$300+ | 높음 |

---

## 결정 (Decision)

**동기 DB 저장**을 채택한다. 메시지 수신 즉시 MySQL에 INSERT 후 WebSocket으로 브로드캐스트한다.

- MySQL RDS는 초당 수천 건의 INSERT 처리 가능
- Cherry 예상 트래픽은 초당 수십 건 이하
- 추가 인프라 비용 $0, 데이터 일관성 보장

---

## 전환 기준

초당 메시지 100건 초과, DB 커넥션 풀 포화 빈번, 또는 다중 서버 전환 시 메시지 큐 도입을 재검토한다.

전환 경로: 동기 DB → Redis 버퍼 → RabbitMQ (단계적)
