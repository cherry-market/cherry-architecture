# ADR-008: 채팅 이미지 첨부 전략

- **상태**: 확정
- **일자**: 2026-02-15
- **참여**: Claude (인프라 비용 분석, 보안 리스크 평가) + 사용자 (최종 의사결정)

---

## 맥락 (Context)

Phase 6에서 1:1 채팅 기능을 구현했으며, 이제 채팅에 이미지 첨부 기능을 추가할지 여부를 결정해야 한다.

### 현재 상황

- **채팅**: STOMP over WebSocket으로 텍스트 메시지만 지원 (메시지 저장은 MySQL 동기 저장)
- **인프라**: AWS EC2, RDS MySQL, S3, Lambda, CloudFront
- **이미지 파이프라인**: 상품 업로드 시 Presigned URL → S3 업로드 → Lambda 리사이즈 → 서버 콜백 구조
- **예상 DAU**: 100~500명

### 핵심 고려사항

1. **개인 운영 중고거래 플랫폼 특성**: 비용 폭탄 위험이 가장 치명적
2. **보안**: 새로운 업로드 엔드포인트 노출 시 공격 벡터 증가
3. **MVP 속도**: 채팅 이미지는 선택 기능 (필수 아님)
4. **UX**: 있으면 좋지만, 텍스트만으로도 거래 가능

---

## 선택지 (Options)

### 옵션 A: 채팅 이미지 미도입 (MVP)

**설명**: 채팅에서 상품 이미지 링크 공유만 허용. 직접 업로드 불가.

| 항목 | 내용 |
|------|------|
| **구현** | 기존 링크 공유 기능만 사용 (추가 구현 없음) |
| **비용** | $0 (추가 비용 없음) |
| **개발 공수** | 0일 |
| **보안 리스크** | **없음** — 업로드 엔드포인트 미노출 |
| **UX 제약** | 채팅에서 직접 사진 전송 불가 |

**장점**:
- 추가 인프라/비용 없음
- 업로드 악용 위험 제거
- 개인정보 유출 위험 최소화
- MVP 출시 속도 우선

**단점**:
- 사용자 편의성 다소 제한
- 채팅 중 이미지 업로드 → 상품 페이지 복사 → 공유의 번거로움

---

### 옵션 B: 원본 그대로 업로드 + 제공

**설명**: 사용자가 업로드한 원본 이미지(5~10MB)를 그대로 저장하고 제공.

| 항목 | 내용 |
|------|------|
| **비용** | **높음** (데이터 전송량 급증) |
| **보안 리스크** | **매우 높음** |
| **확장성** | 나쁨 |

**단점**:
- 스토리지 비용 상승 (원본 크기 그대로)
- **데이터 전송 비용 폭탄 위험**: 대역폭 무제한 소비 가능
- Presigned URL 발급 API 노출 → **비인가 업로드 공격 벡터**
- **결론**: MVP 단계에서 **부적합**

---

### 옵션 C: thumb + view 구조 (향후 도입)

**설명**: 이미지를 용도별로 리사이즈하여 비용 통제. 기존 Lambda 파이프라인 재사용.

#### 이미지 계층 정의

| 계층 | 용도 | 크기 | 주의사항 |
|------|------|------|---------|
| **thumb** | 채팅 메시지 미리보기 | 150px x 150px, ~20KB | WebP + 품질 70% |
| **view** | 클릭 시 확대 보기 | 1600px 또는 2048px, ~800KB~1MB | JPEG/WebP, 품질 85% |
| **original** | 선택적 접근 (향후) | 원본 또는 최대 5MB로 제한 | S3 Lifecycle으로 자동 삭제 |

#### 구현 방식

1. 사용자가 채팅에서 이미지 업로드 요청
2. Presigned URL 발급 (rate-limit 적용)
3. 클라이언트가 S3에 원본 업로드
4. S3 이벤트 → Lambda 트리거
5. Lambda: 원본 → thumb 생성 → view 생성

#### 비용 분석

| 항목 | 월 비용 | 비고 |
|------|--------|------|
| **S3 스토리지** | ~$1~5 | thumb + view 합산, Lifecycle 자동 삭제 |
| **데이터 전송** | **월 무료 범위 내** | view 기준 월 ~5~10GB 수준 |
| **Lambda 호출** | 거의 무료 | 무료 티어 범위 내 |

**결론**: **비용 통제 가능**.

#### 보안 완화 방안

| 위험 | 완화 방안 |
|------|----------|
| Presigned URL 발급 API 악용 | Rate Limit 적용 |
| 파일 크기 폭탄 | 업로드 크기 제한 |
| 악성 파일 업로드 | 이미지 형식 검증 (JPEG, PNG, WebP만 허용) |
| 스토리지 누적 | S3 Lifecycle 자동 삭제 |
| 비용 폭탄 | AWS Budgets 예산 알림 |

#### 장점

- 기존 Lambda 리사이즈 파이프라인 재사용 (새 인프라 불필요)
- 비용을 완전히 통제 가능
- thumb으로 채팅 로드 최소화
- view로 사용자 경험 충분함

#### 단점

- 구현 복잡도 증가
- Lambda 비용 계산 필요
- 클라이언트 사전 리사이즈 구현 권장 (선택적)

---

## 결정 (Decision)

### 1단계 (MVP): **옵션 A — 채팅 이미지 미도입**

- 채팅에서는 텍스트 메시지만 지원
- 상품 이미지 링크 공유로 충분

**근거**:
- 개인 운영 플랫폼의 비용 리스크 최우선
- 보안 엔드포인트 미노출로 공격 벡터 차단
- MVP 출시 속도
- 사용자 피드백 없이 미리 기능 구현할 필요 없음

### 2단계 (트래픽 검증 후): **옵션 C — thumb + view 구조 도입**

**도입 기준** (다음 중 하나 이상 충족):
- 사용자 피드백에서 이미지 전송 요청 빈도 증가
- 실제 트래픽 패턴 확인 후 비용 영향도 무시할 수 있는 수준 검증
- DAU가 지속적으로 100 이상 유지

### 옵션 B는 제외

**이유**: 원본 이미지 무제한 저장 시 비용 예측 불가능. 개인 운영 플랫폼에서 감수 불가능한 리스크.

---

## 트레이드오프 (Trade-offs)

### 1단계 (MVP)에서 감수하는 것

- 채팅에서 이미지 직접 업로드 불가
- 사진 공유 시 링크 복사 → 공유의 번거로움

### 1단계에서 얻는 것

- **비용**: 추가 $0 (개인 운영에서 중요)
- **보안**: 업로드 엔드포인트 미노출 → 비인가 접근 차단
- **간결성**: 채팅 이미지 저장/로직 미필요 → 운영 단순
- **속도**: MVP 출시 가능 시간 단축
- **유연성**: 향후 실제 사용자 수요에 따라 옵션 C 도입 가능
