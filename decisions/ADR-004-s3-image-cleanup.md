# ADR-004: S3 이미지 정리 전략

- **상태**: 확정
- **일자**: 2026-02-09
- **참여**: Claude (코드베이스 분석, 비용 산출) + ChatGPT (리서치/아키텍처 제안)

---

## 맥락 (Context)

상품 삭제(soft delete) 및 이미지 수정(개별 이미지 삭제) 시, S3에 남아있는 이미지 객체의 정리 전략을 결정해야 했다.

현재 구조:
- S3 버킷: `cheryi-product-images-prod` (ap-northeast-2)
- 이미지 1장당 S3 객체 3개:
  - `products/original/{imageKey}` — 원본 (2~8MB)
  - `products/detail/{imageKey}` — 리사이즈 1280px (200~500KB)
  - `products/thumb/{imageKey}` — 썸네일 256x256 (5~20KB)
- 상품당 최대 10장 = 최대 30개 S3 객체

---

## 선택지 (Options)

| 선택지 | 설명 | 개발 공수 | S3 비용 영향 |
|--------|------|-----------|-------------|
| **A) 동기 즉시 삭제** | API 호출 시 S3도 함께 삭제 | 중간 | 없음 |
| **B) 비동기 즉시 삭제** | API 응답 후 별도 스레드로 S3 삭제 | 중~높 (task 테이블, 워커, 재시도) | 거의 없음 |
| **C) 배치 정리** | 매일 1회 스케줄러로 일괄 삭제 | 낮음 | 최대 24시간 지연 |
| **D) S3 Lifecycle Rule** | 태그 기반 자동 만료 | 낮음 | 만료 지연 (1일 단위) |
| **E) 정리하지 않음** | S3에 그대로 유지 | 없음 | 지속 증가 |

### 비용 상세 분석

**S3 스토리지 비용 (ap-northeast-2 기준):**

| 시나리오 | 총 용량 | 월 비용 (S3 Standard) |
|----------|---------|----------------------|
| 상품 1,000개 × 5장 × 5MB | ~25GB | ~$0.58 |
| 상품 10,000개 × 5장 × 5MB | ~244GB | ~$5.60 |
| 삭제 유예 30일분 (월 1,000건 삭제 추정) | ~25GB 추가 | ~$0.58 추가 |

**개발 비용 비교:**

| 선택지 | 구현 시간 | 유지보수 복잡도 | 장애 시 영향 |
|--------|-----------|-----------------|-------------|
| A) 동기 삭제 | 1일 | 높음 (DB/S3 불일치 처리) | API 응답 지연/실패 |
| B) 비동기 삭제 | 2~3일 | 높음 (task 테이블, 워커, 재시도) | 워커 장애 시 적체 |
| **C) 배치 정리** | **0.5일** | **낮음** | 최대 1일 지연 (무해) |
| D) Lifecycle | 1시간 (설정) | 낮음 | 세밀한 제어 불가 |
| E) 안 함 | 0 | 없음 | S3 비용 증가 |

## 결정 (Decision)

**단일 배치 정리 (C안 기반 단순화)** 를 채택한다.

### 동작 방식

1. **삭제/수정 시점**: DB 처리만 수행, S3는 건드리지 않음
   - 상품 삭제: `deleted_at` 세팅
   - 이미지 개별 삭제: ProductImage row 삭제 또는 `deleted_at` 세팅

2. **매일 1회 `@Scheduled` 배치**:
   - **상품 soft delete 30일 경과분**: `product.deleted_at <= NOW() - 30일`인 상품의 전체 이미지 S3 객체 삭제
   - **수정 중 삭제된 orphan 이미지**: ProductImage에서 삭제되었지만 S3에 남아있는 객체 삭제
   - S3 `DeleteObjects` API로 최대 1,000개씩 일괄 삭제

### 범위 밖 (추후 고려)
- S3 Lifecycle Rule (태그 기반): 배치가 안정적으로 동작한 후 2차 안전장치로 추가
- `s3_delete_tasks` 테이블 + 워커: 현재 규모에서는 과투자

---

## 트레이드오프 (Trade-offs)

### 감수하는 것
- 삭제 후 최대 24시간 동안 S3에 고아 객체 존재
  - 완화: DB에서 이미 제거되어 누구에게도 URL이 노출되지 않으므로 실질적 문제 없음
- soft delete 유예 30일간 S3 비용 지속 (월 $0.58 추가 수준)
  - 완화: 복구 가능성 확보라는 가치와 비교 시 무시 가능한 비용

### 얻는 것
- API와 S3 정리가 완전 분리 → API 응답 지연/실패 위험 제거
- 구현 0.5일로 최소 공수
- "soft delete + 유예 기간 + 배치 정리" 패턴 자체가 실무 감각을 보여줌
- DB/S3 불일치, 롤백, 재시도 등 복잡한 문제를 원천 회피
