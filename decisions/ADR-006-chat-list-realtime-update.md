# ADR-006: 채팅 목록 실시간 갱신 전략

- **상태**: 확정
- **일자**: 2026-02-13

---

## 맥락 (Context)

채팅 목록 화면에서 새 메시지 도착 시 실시간 갱신이 필요했다. 이미 STOMP over WebSocket 인프라가 구축된 상태에서 갱신 방식을 결정해야 했다.

---

## 선택지 (Options)

| 선택지 | 변경 없을 때 트래픽 | 실시간성 | 추가 인프라 |
|--------|-------------------|---------|------------|
| Short Polling (15초) | 15초마다 요청 (낭비) | 최대 15초 지연 | 없음 |
| **WebSocket 푸시** | **0** | **즉시** | **이미 구축됨** |
| SSE | 0 | 즉시 | WebSocket과 중복 |

---

## 결정 (Decision)

**WebSocket 푸시**를 채택한다. 기존 STOMP WebSocket 인프라를 활용하여 새 메시지 도착 시 채팅 목록을 즉시 갱신한다.

- 폴링 대비: 불필요한 HTTP 요청 제거, DB 쿼리 감소
- 추가 비용: $0 (기존 인프라 활용)
- HTTP 요청 오버헤드(~500 bytes) 대비 WebSocket 프레임(~6 bytes)으로 대역폭 절감

---

## 참고: 폴링의 스레드 비용

Short Polling은 스레드를 "고정 점유"하지 않는다 (Long Polling과 구분). 요청당 ~30ms 사용 후 반환하므로, 100명 기준 평균 0.21개 스레드를 사용한다. 스레드 비용이 아닌 불필요한 트래픽이 폴링의 주요 단점이다.
